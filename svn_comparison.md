1. Почему в Git ветвление "дешёвое", а в SVN — "дорогое"?
В Git ветка — это просто указатель (ссылка) на коммит, который весит всего 41 байт. При создании ветки Git не копирует файлы — он лишь создаёт новую ссылку на существующий коммит. Поэтому создание ветки происходит мгновенно, независимо от размера проекта.
В SVN ветка создаётся путём копирования всей директории в репозитории (через операцию svn copy). Хотя SVN оптимизировал этот процесс (использует "ленивое копирование"), ветка всё равно создаётся как отдельный объект в репозитории, и операции с ветками требуют обращения к серверу. Это делает ветвление более "тяжёлым" как по ресурсам, так и по скорости.
2. Можно ли в SVN сделать коммит без интернета? Почему?
Нет, нельзя. SVN — это централизованная система контроля версий (CVCS). Все коммиты отправляются напрямую на центральный сервер. Без подключения к серверу операция svn commit невозможна — SVN не имеет локального хранилища истории.
В отличие от этого, Git — распределённая система (DVCS). Каждый коммит сохраняется локально, и только git push отправляет изменения на удалённый сервер. Поэтому в Git можно работать и коммитить офлайн.
3. В каких сценариях SVN до сих пор может быть предпочтительнее Git?
Крупные бинарные файлы (дизайн-макеты, видео, 3D-модели). SVN лучше работает с бинарниками, поддерживает lock-механизм (файл можно "заблокировать" для редактирования).
Централизованный контроль доступа. В SVN можно гибко настраивать права на уровне отдельных папок и файлов через сервер.
Простые проекты без необходимости ветвления. Если команда маленькая и ветки не нужны, SVN проще в освоении.
Наследие. Многие старые корпоративные проекты всё ещё используют SVN, и миграция на Git экономически нецелесообразна.
Частичный checkout. В SVN можно скачать только нужную папку репозитория, а в Git клонируется вся история целиком.
