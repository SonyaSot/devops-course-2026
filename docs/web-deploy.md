
# Практическая работа №6. Веб-сервер и деплой

## Цель работы

Научиться устанавливать и настраивать веб-сервер Nginx, использовать HTTPS, переносить файлы через rsync и автоматизировать развёртывание сайта с помощью Bash-скрипта.

## 1. Установка Nginx

Работа выполнялась на виртуальной машине Ubuntu Server 24.04.5 LTS, которая была подготовлена в практической работе №5.

Для установки использовались команды:

```bash
sudo apt update
sudo apt install -y nginx
```

Проверка службы:

```bash
systemctl status nginx --no-pager
sudo ss -tlnp | grep nginx
```

Служба находилась в состоянии active (running), веб-сервер принимал подключения на порту 80.

Проверка с Windows:

```powershell
curl.exe -I http://devops.local
```

Сервер вернул HTTP/1.1 200 OK.

## 2. Размещение сайта

Для сайта создан каталог:

/var/www/devops-site

Владельцем каталога назначен пользователь devops.

Первоначально был создан файл index.html с заголовком devops.local: placeholder.

Конфигурация сайта размещена в файле:

/etc/nginx/sites-available/devops-site

Для активации использовалась символическая ссылка в sites-enabled. Стандартная конфигурация Nginx была отключена.

Проверка:

```bash
sudo nginx -t
sudo systemctl reload nginx
```

После применения настроек в браузере открывалась собственная HTML-страница.

## 3. Настройка HTTPS

Для защищённого соединения создан самоподписанный сертификат с именем devops.local.

Закрытый ключ:

/etc/ssl/private/devops.key

Сертификат:

/etc/ssl/certs/devops.crt

Срок действия сертификата — один год.

Права закрытого ключа — 600. Права сертификата — 644.

В конфигурации Nginx настроены:

- перенаправление HTTP на HTTPS с кодом 301;
- порт 443;
- TLS 1.2 и TLS 1.3;
- использование сертификата devops.crt.

Проверки показали:

HTTP — 301 Moved Permanently.
HTTPS без доверенного сертификата — ошибка проверки.
HTTPS с параметром --cacert — 200 OK.

При просмотре сертификата установлено, что subject и issuer совпадают, поскольку он самоподписанный.

После настройки создан снимок VirtualBox 04-nginx-https.

## 4. Доставка сайта через rsync

Разработка велась в ветке feature/web-deploy.

В репозитории создан каталог site с файлами:

- index.html — главная страница;
- 404.html — пользовательская страница ошибки.

Доставка выполнялась командой:

```bash
rsync -avz --delete --chmod=D755,F644 site/ devops:/var/www/devops-site/
```

Сначала был выполнен пробный запуск с --dry-run, затем фактическая доставка.

После синхронизации сайт DevOps Course 2026 открылся в браузере.

Проверка несуществующей страницы показала ответ 404 Not Found и отображение собственной страницы ошибки.

Права на сервере:
- каталоги — 755;
- файлы — 644.

## 5. Автоматизация деплоя

Разработан сценарий scripts/deploy.sh.

Он проверяет наличие index.html, отсутствие незакоммиченных изменений, выполняет синхронизацию rsync и проверяет доступность сайта через HTTPS.

Поддерживается пробный запуск:

```bash
bash scripts/deploy.sh --dry-run
```

Обычный запуск:

```bash
bash scripts/deploy.sh
```

Проведено пять проверок:

1. Пробный запуск — код 0.
2. Успешная доставка зафиксированных изменений — код 0.
3. Отказ при незакоммиченных изменениях — код 1.
4. Отказ при остановленном Nginx — код 1.
5. Отказ при отсутствии index.html — код 1.

После тестирования главная страница восстановлена, а Nginx снова запущен.

## 6. Проверка прав доступа

При установке прав 600 на файл index.html Nginx вернул 403 Forbidden. В журнале ошибок появилась запись Permission denied.

Проверены права каталога:

| Права | HTTP-код |
|---|---|
| 755 | 200 |
| 750 | 403 |
| 744 | 403 |
| 711 | 200 |

При правах 711 пользователь www-data мог читать файл по известному имени, но не мог просматривать список файлов каталога.

Отдельно проверена доставка через rsync без --chmod. На сервер были перенесены права 777, после чего пользователь www-data смог изменить страницу.

Повторный запуск deploy.sh восстановил исходное содержимое и безопасные права 755 и 644.

## 7. Анализ HTTP и журналов

Командой curl -v проверен HTTPS-запрос.

Результаты:
- TLS 1.3;
- HTTP/1.1;
- код 200 OK;
- Nginx 1.24.0;
- Content-Type: text/html;
- Content-Length: 323.

Для исследования журнала были отправлены запросы к главной странице и путям /admin, /wp-login.php и /.env.

Команда подсчёта ответов:

```bash
sudo awk '{print $9}' /var/log/nginx/devops-site.access.log | sort | uniq -c | sort -rn
```

Полученные результаты:

| Код | Количество |
|---|---:|
| 200 | 23 |
| 404 | 10 |
| 403 | 4 |

Запросы к .env и wp-login.php часто используются автоматизированными сканерами для поиска потенциально уязвимых ресурсов.

## Вывод

В практической работе был установлен и настроен Nginx, создан сайт с поддержкой HTTPS и собственной страницей 404. Настроена доставка файлов через rsync и разработан скрипт автоматического деплоя.

Дополнительно изучены права доступа Linux, способы диагностики ошибок Nginx и анализ HTTP-запросов по журналам сервера.
